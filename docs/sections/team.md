## Content and composition

Add **Team** under **Trust & information**. Merchant-owned **Team** metaobjects (type `team`) are the only person data source. **Show** is the first control: One member uses the first selected entry, Selected members uses the ordered selection (up to 50), and All members shows active entries (up to 250) by Display order. Empty single/selected modes remain empty; they never fall through to the whole team. The existing `people` ID is preserved. Shopify does not support `visible_if` on metaobject lists, so the single shared picker remains visible with conditional explanatory paragraphs for each mode; this is an explicit platform limitation of the requested three-mode UI. The existing development placement was migrated explicitly to All members; migrating any future older selected placement must set Selected members to preserve its meaning. Draft entries never appear. Single/two-card layouts are bounded; the full grid uses three desktop columns, two tablet columns and one phone column.

Entry fields: Name (required, administrative display name and accessible name), Name on card (optional multiline display), Role, Description, Portrait (required image reference), LinkedIn, Instagram, Phone (number without `tel:`), Email (without `mailto:`), Display order (integer), Real person (boolean). Real person controls honest Person structured data; it does not control display. Mark mascots false. Entry status provides global active/draft visibility. All merchant text remains authored German source content, with the definition's translation capability enabled.

The published theme's `section-team` settings are the migration source. `scripts/setup-team.mjs --source=/path/to/config/settings_data.json` is read-only by default; `--apply` creates the definition and missing entries, preserves existing entries, reuses exact existing Files image IDs, retains ordering and multiline names, and verifies returned fields/status. Backups are outside the repository with private permissions. The 2026-10-02 import contains nine active entries (including Canette) and two drafts (Karim and Nina), retaining original copy including source spelling. No published-theme files were modified. Definition creation requires `write_metaobject_definitions`; entry writes require `write_metaobjects`. The app scope update was explicitly approved in the session.

## Cards and interaction

Portraits use responsive `image_url`/`image_tag`, selected Shopify image focal points, shared large radii and `--shadow-panel`. Only the outer card casts a shadow; no hover lift or image scaling. Section heading uses Section. Names use the shared Panel name role and roles/descriptions Panel info, resolving against the card’s inline-size container. This merchant-requested card composition exception makes names substantially larger while information stays at least 1rem. Padding and wrapping keep content in normal flow, so long/enlarged text can grow the card. Portraits overscan the clipping boundary by one pixel with no dark backing or image radius, preventing seams behind the rounded edge. Heading font selects Erode (authored case) or Newake with shared line height. Names are standalone headings with no adjacent-icon optical offset. Existing social marks are logo artwork; email/phone use Untitled UI Line icons at the default 1.25rem icon size.

Fine-pointer hover and keyboard focus within the card crossfade the scrim and description/contact area with shared Base duration/easing. The bottom role/name remains visible. On touch/coarse or non-hover devices the details remain visible, requiring no hidden first-tap gesture. Contacts are native links with at least 44px height, accessible translated names, and shared inverse pill/sweep styling. Only configured contacts render; social links open a new tab with safe rel attributes, telephone/email keep native protocols. No JavaScript is required for cards. Reduced motion settles immediately. The card itself is not a link or click target.

Video is a separate [Video](video.md) section. The latest dev template was backed up outside the repository before this migration. Both sections can be moved, hidden, duplicated and removed independently.
