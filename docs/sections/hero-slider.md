# Hero slider

Source: `sections/hero-slider.liquid`, `assets/hero-slider.css`, `assets/hero-slider.js`.

## Purpose and placement

Reusable media-led introduction, based on frame `11621:56047`. A rounded 16:9 image/video panel sits above a left-aligned headline and linked button. Persistent shared circular previous/next buttons sit to the right of the headline on desktop and beside the action on phones. Optional progress bars select slides; they default to hidden and are disabled on the development homepage. There is no pause/play button. The development homepage uses this section; the original Hero remains available for existing placements. Other homepage content is preserved from the latest development-theme pull.

## Shared data: Slides

Merchant-owned metaobject type `slides`, definition name **Slides**, managed in Content → Metaobjects. Public storefront read, publishable and translatable. Draft entries do not appear on the storefront.

| Field | Type | Contract |
| --- | --- | --- |
| Name | Single-line text, required | Internal selection label |
| Media | File reference, required | One image **or** video; validated to Image/Video |
| Headline | Multi-line text, required | Visible below media; authored line breaks preserved |
| Link | URL, optional | Media and button destination; page, product, collection or external URL |
| Button label | Single-line text, optional | Action text; blank uses the translated Learn more label. No Link means no button. |

No separate media-type selector is necessary: Shopify's file picker selects either supported type. A shared entry update affects every slider referencing it. Links are editorial URLs, not inferred products; translations may supply localized URLs. Each placement chooses All or Selected; selected mode is the default so existing campaigns remain unchanged. All mode automatically includes active public entries in Shopify’s default order, up to the Liquid pagination maximum of 250. Larger libraries require Selected mode; custom ordering also uses Selected. `scripts/setup-slides.mjs` defaults to a read-only plan, creates missing definitions/entries only with `--apply`, backs up existing records, and refuses incompatible existing schemas. Its repeatable migration adds only the optional Button label field to the existing definition, preserving entries and translations. Starter entries reuse existing store media; no assets are silently uploaded.

## Editor controls and dependencies

- **Slides:** Show all slides / Show selected slides (default). Selected uses the existing ordered native picker, up to six entries. All ignores the saved selection and reads the public Slides library. Shopify rejects `visible_if` on `metaobject_list` (confirmed by ValidSchema); the picker must remain visible in both modes, labelled Selected slides with explicit help. This is a platform exception to conditional visibility, not a hidden header workaround.
- **Layout:** Narrow / Editorial / Page width uses shared content widths; Page width (120rem / 1920px including shared side gutters) is the default and the development homepage selection; Media always stays 16:9. In landscape viewports, the enhanced section fills the viewport below the header; equal top, middle and bottom spaces center the media and caption. Media width shrinks as needed to fit the available height. Very short landscape viewports grow naturally instead of squeezing the caption below a readable width. The old height_mode and mobile_shape IDs are retained for saved-content compatibility, ignored by rendering and hidden in every mode with intentionally contradictory visibility conditions.
- **Headings:** Erode/Newake; Uppercase appears only for Newake. First slide heading chooses H1 or H2, all subsequent headings use H2. Use H1 for the main page introduction only. Slideshow label names the region for assistive technology. Heading alignment selects Left (default) or Center, with no dependent fields. It aligns text within the caption column, leaving media placement and navigation unchanged. Existing saved Center values remain supported. Heading size selects shared Title / Section / Display / Hero roles (Small / Standard / Large / Extra large, Large default). The development homepage selects Small: 30px on phones through 45px on desktop, matching the reference desktop caption without changing shared heading rhythm. Space above heading is 16–80px, default 40px, capped at 6vw on smaller screens.
- **Appearance:** Show slide indicators defaults off and has no dependent fields. It independently controls the media progress bars, including manual indicators when autoplay is off; previous/next navigation remains available for multiple slides. Ambient light (on by default) reveals Glow intensity (0–100%, default 40%), Glow spread (0–80px, default 24px) and Glow softness (16–120px blur, default 40px). Off/zero creates no glow canvases or sampling tasks and uses the shared soft panel shadow on the outer rounded frame. The media then has no second shadow; the outer treatment remains visible during the oval reveal rather than being clipped with the image. This is a per-placement presentation control, not shared slide content.
- **Playback:** automatic switching; Time per slide appears only when enabled (4–15 seconds, six by default). The same duration applies to image and video slides; short videos loop, long videos advance at that duration. Videos are muted ambient editorial media, with no native player controls.
- Shared Visibility and Section background groups. Background offers Transparent, Colored and Dark mode. Colored enables Surface; only its Custom color option enables the color picker. Dark mode hides both dependent fields and uses the shared black canvas (the same foreground role as the top header bar), inverse heading text, light CTA with dark text, and dark-gray circular arrows with light icons. Hover/focus invert button fills and labels through the existing shared motion pattern. The choice is opt-in; saved default/background values remain unchanged.

The section contract covers every select/checkbox and dependent field. Media/headline/link/button label are central content, not duplicated section fields or blocks. Shopify metaobject forms do not need conditional media fields because there is one polymorphic file picker.

## Rendering and motion

Shopify responsive image URLs preserve the saved focal point. First media is eager/high-priority only in the first two sections; later images are lazy. Videos use Shopify sources and a preview poster, `preload=none`, muted/inline playback. Missing media leaves a neutral placeholder, while an empty selection renders only an administrative message in the editor. No bundled fallback photo.

The media frame and its ambient canvas form the lower stacking layer; the caption has an explicit higher layer so glow never paints over headline glyphs or the action button, including during caption transitions. Media has one rounded clip, one-pixel overscan and shared panel shadow, with no dark backing. Heading defaults to the shared Display role and font-specific line height/casing. No custom typography scales. Media crossfades and text fades/rises by .75rem with shared Slow (360ms) motion; rapid selection interrupts smoothly. All slides reserve the maximum complete caption height, avoiding page layout jumps. Headline measure is capped at 62.5rem (1000px at the default root size), within the available caption column. Left alignment keeps its start edge aligned with the media; saved Center alignment centers the capped headline within that column. Each button follows its own headline with a 16px gap. Desktop Newake beside the navigation uses the shared optical offset; standalone phone headings do not. Phone navigation smoothly follows the active action row. Shared round-arrow buttons are 72px on desktop and 48px on phones, with 32px and 24px icons respectively.

The slide timer pauses during mouse hover over media, actions or controls and resumes from its elapsed position on leaving. Headline hover does not pause it. Keyboard focus in the action or paging controls pauses switching, preserving the focused destination. Manual slide selection restarts the selected slide’s duration. Video playback and its glow are independent of that timer: they continue on hover and keyboard focus, even when automatic slide switching is disabled. Inactive video pauses and resets; offscreen/hidden-tab/editor states suspend playback. Reduced motion uses static video posters and disables slide autoplay/transitions. There is no pause/play control, as requested. Native custom-element lifecycle cleans listeners, observers and callbacks on section removal/reload.

Indicators have 44px-minimum hit targets, `aria-current`, named destinations and a decorative progress fill. Keyboard arrows/Home/End move among indicators. Manual selection announces the slide; automatic switching does not repeatedly announce. Inactive slides become inert/hidden from assistive technology. Each active destination has one keyboard link in its button; the media repeats it as a pointer target. No JavaScript: all slides and links stack in source order; videos retain static posters and control buttons stay hidden.

## SEO and limitations

Slide headlines/links are server-rendered. This is a promotional presentation, not a separate typed content entity: it does not emit Product/Offer/VideoObject claims or duplicate the destination's structured data. No honest VideoObject publication date is available from these fields. Existing page-level structured data remains authoritative.

## Ambient rendering budget

The native helper in `hero-slider.js` lazily adds a decorative, aria-hidden 64×36 canvas behind each visited slide’s single rounded media clip. Images draw once per source/crop; ResizeObserver updates the cover crop and Shopify percentage focal point when geometry changes. No full-resolution duplicate image or video player is created. Video posters use a low-priority, 128px Shopify thumbnail only when their glow is needed.

Active playing video is sampled no faster than every 125ms (at most 8Hz): a timeout requests one decoded video frame where `requestVideoFrameCallback` is available; other browsers use a throttled ready-state/current-time check. Frame colours blend at 35% over the preceding sample to soften changes. Sampling stops on pause, waiting, ended, inactive slide, offscreen, hidden tab, reduced motion and removal. Reduced motion draws the static poster even if previously animated. Failed canvas/decoder drawing omits the decoration without affecting media/links. No pixel readback, data URL export or cross-origin pixel access is required.

The small raster extends 24px beyond the panel by default (spread capped at 6vw) with 40px blur (halved on phones) and modest saturation; opacity remains 40%. Spread and softness are adjustable within bounded ranges. Larger blur increases compositing cost without increasing sampling frequency or canvas resolution. It crossfades with its slide and fades in using shared Slow motion, disabled for reduced motion. This adds GPU/compositing work; the small sample buffer is not a promise of zero rendering cost. No third-party ambient dependency, global animation loop or second video decoder.

The [design studio](http://127.0.0.1:9293/#AmbientLight) runs the same stylesheet/custom element with Image/Video, 0–100% intensity, spread, softness, enabled, shared width, heading size/gap, reset and copy-settings controls. Changes are local preview values, not store writes. The demo uses the existing bundled Soda image and Shopify-hosted Team video (480p); no video download occurs before selecting it.

Icons: reuse the shared button arrow masks and round-arrow interaction pattern, sourced from Untitled UI. Optional indicators remain over the media. Navigation buttons stay visible whenever multiple slides are enhanced.

## Initial layout

Small inline startup styles cover the interval before the external stylesheet arrives. JavaScript-enabled split-caption heroes reserve landscape viewport space before enhancement and stay visually hidden until the first fitted layout uses settled font metrics. Header height is read directly during fitting, avoiding dependence on another script's initialization order. Startup waits for fonts with a 2.5-second limit, then measures and starts the entrance in the same animation frame. The first media panel reveals from top to bottom through the shared button sweep’s 180% × 300% oval, using the gentler shared UI easing and a moving elliptical clip rather than a rectangular wipe or image fade, over three times the shared Slow duration (1080ms). The headline starts at 200ms, action at 260ms and paging at 320ms (a subtle 60ms stagger), overlapping the panel reveal and each other instead of waiting for each preceding animation to finish. Headline/action use Slow (360ms); paging uses Base (260ms). Inactive slides are fully hidden with transitions disabled throughout entrance, so no second image can appear behind the oval. Ambient glow is active during the oval reveal, using its existing paint-ready fade and remaining behind the media/caption. It does not wait for entrance completion. Text rises 8px while fading; paging only fades at its final measured position. Invisible action/paging controls remain inert until entrance completion. Autoplay starts after the entrance; manual slide selection finishes it immediately. Reduced motion and Theme Editor rendering skip the entrance. Disconnect and motion-preference changes cancel pending animations. Inactive captions are hidden immediately during slide changes, preventing overlapping headlines while retaining media crossfades. A four-second CSS delay (independent of reduced-motion animation durations) exposes the source content if enhancement fails to load. No-JavaScript visitors immediately retain the source-order content and links. Very late fonts beyond the startup limit can still change text metrics; the bound preserves access on failed requests. Poster Slideshow and legacy studio layouts are excluded. Cold-cache browser checks with 350ms network latency at 390px and 1440px recorded no visible pre-fit frames and a single media width from first reveal onward. Sequenced-entrance checks sampled intermediate oval/headline/action/paging frames on phone and desktop and confirmed exactly one visible slide throughout the panel sweep. Cold loads in both motion modes recorded one fitted visible media width, at most one visible caption and a single visible paging position. All 32 slide/viewport checks and the script-disabled native-link checks passed; blocking the slider bundle separately confirmed the timed content fallback.

## Directional oval slide transition

Playback includes **Oval slide transition**, enabled by default and independent of autoplay, indicators and ambient light. It has no dependent fields. Off retains the existing fade. On reveals the incoming media through the entrance sweep’s fixed oval rotated 90 degrees: `ellipse(150% 150%)`, centered vertically, travelling from −150% to 0% horizontally for Next, mirrored from 250% to 100% for Previous, with a subtle 1.045-to-1 depth scale. It uses the entrance sweep’s three Slow durations and shared UI easing. The outgoing panel remains underneath, inert and hidden from accessibility, while only the new caption is visible; paging remains available. Autoplay wraps forward and waits for the transition to finish before timing the next slide. Rapid navigation settles the previous transition before starting the latest, with at most two painted panels. Reduced motion settles immediately, including a preference change during motion; section removal cancels animations. No schema IDs, stored slides, media sources or first-load reveal behavior are replaced.

Verified on the two real homepage slides at 1440px and 390px, including sampled 0/25/50/75/100% oval frames in both directions, forward wrap, rapid reversal, disabled-toggle fade, reduced-motion activation during a transition and subsequent immediate navigation. Exactly one active slide and at most one inert outgoing panel remain; animation cleanup leaves no outgoing panel. Zoom stays inside the rounded media clip. Phone has no overflow. Full checks, editor contracts, JS syntax and header-aware JSON validation passed; the isolated test browser was closed.

Oval refinement: the mask no longer grows from a point or moves diagonally across the media. Its fixed normalized radii start from the entrance mask’s swapped axes, with the vertical radius increased to 150% to soften and flatten the leading curve. The sweep stays vertically centered. Desktop Next and phone Previous intermediate frames were visually checked; both begin fully outside the panel and finish covering its corners. Existing timing, depth scale, toggle, accessibility and cancellation behavior remain unchanged.

Hosted CSS duration correction (2026-10-08): Shopify can minify custom-property durations from milliseconds to seconds. Both initial reveal/staggers and slide sweeps now normalize `ms` and `s` to Web Animations milliseconds. Previously the hosted 0.36s Slow token was parsed as 0.36ms, making the 1,080ms oval effectively invisible at 1.08ms despite an enabled configuration. Development and hosted theme timing now use the same values.
