# Press articles

Source: `sections/press-articles.liquid`, `assets/press-articles.css`, shared `snippets/link-box.liquid` and `assets/editorial-content.css`.

Select up to 50 **Press** entries in desired publication order. Each entry's ordered **Articles** references active **Press article** objects with required Title and URL. Shopify native references let editors create/select multiple paired items from the parent; there are no parallel arrays, manually authored JSON or fixed article slots. The Articles field is limited to 50 references per publication so every supported entry fits Shopify's Liquid loop limit; sections do not enumerate unrelated entries. Existing merchant records are never rewritten by rendering.

The renderer displays every available nonempty article as a shared Link box, with its publication logo on the left instead of a separate publication heading. It preserves the saved title and URL. Publications without valid articles disappear; an entirely empty selection emits only editor guidance. Native external links open a new tab with `noopener noreferrer` and a translated announcement. No JavaScript is required. Section titles use Section and link labels Compact. Each logo has the publication name as alternative text. Long titles wrap instead of truncating. Existing link hover/focus/reduced-motion behavior and panel shadows are reused.

Editor groups: Content (Heading, Heading font, Press entries), Visibility, Section background. Heading font applies to the section title (including its accessible fallback when blank). Only Custom background exposes Color. The single native picker remains relevant without a source/mode switch. All schema scenarios are reviewed in the editor contract.

Visible links emit one server-rendered ItemList with ordered ListItems, exact title and URL and accurate item count. Fully hidden sections suppress this list. There are no invented NewsArticle authors, dates, ratings or publisher endorsements. Page intro owns the page entity. Repeated section instances use section-specific list IDs.

## Migration and page composition

`scripts/setup-press.mjs --source=/path/to/reviewed-public-snapshot.json` is read-only by default. `--apply` verifies scopes/store, creates missing definitions and entries, reuses Files logos by filename, uploads missing original SVGs through Admin API, verifies values and privately backs up inputs/current data outside Git. Existing entries are preserved. **Press** (type `press`) has required Name/Logo, optional Link and Articles. **Press article** (`press_article`) has required Title/URL. Both are merchant-owned, storefront-readable, publishable and translatable. Drafting a publication hides it from both sections; drafting an article hides that article.

The original published `page.press-media-kit.liquid`, locale content, Files and frontend supply nine names/logos, seven exact article titles/URLs, the original Google Drive kit URL and three billboard photographs. Existing Swiss Drinks logo/photographs are reused. No article was invented for logo-only publications. The new development-only `page.press-media-kit` uses Page intro, Rich text kit action, Press marquee, Press articles, Two-column layout with original campaign photographs and sidebar links, and the separate Press form. The shared footer supplies newsletter signup; the Press form retains its existing optional Klaviyo routing. Existing page assignment is unchanged, and nothing was published.

The reusable Link box snippet now also accepts explicit title/link and an optional logo/alternative text and external-link flag for typed content callers. Existing block settings and styling are preserved. Current imported article links are historical source destinations; third-party redirects, paywalls and content availability remain outside theme control.

## Shared heading casing

**Heading font** uses the standard two-choice Erode/Newake segmented control. **Uppercase headings** appears immediately after it only for explicit Newake and follows the font control's content visibility. On uppercases semantic headings (including rich text); off preserves authored case. Erode ignores saved uppercase. Legacy saved Automatic values remain rendering compatibility only; the editor offers Erode and Newake. See the [heading control standard](../design-system.md#editorial-heading-font-selection). Font/casing schema scenarios are registered; no saved template content or structured data changes.
